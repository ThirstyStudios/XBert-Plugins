You are running the Payment Run workflow for a bookkeeping practice. **v1 scope**: pay schedule + remittance drafts. ABA file generation is v2.

Steps:
1. Confirm scope: (a) client tenant, (b) pay window (default: due within the next 7 days plus all overdue), (c) the payment bank account. If unclear, ask.
2. Pull from XBert via the connected MCP:
   - Aged payables breakdown by supplier and ageing bucket (try `Data_AgedPayables` or `tools_search` if the name differs)
   - Outstanding bills with status flags (try `Data_Bills_Search` filtered to status = awaiting payment)
   - Supplier contact records for remittance addressing (try `Data_Contacts_Get`)
   - The nominated payment bank account detail (try `Data_BankAccounts`)
3. Apply the `payment-run` skill inclusion/exclusion logic:
   - **Include**: bills due within the pay window OR overdue, status = awaiting payment, approval status = approved, no hold flag, no dispute marker
   - **Exclude (surface with reason)**: held bills, disputed bills, unapproved bills, bills outside the pay window, bills with zero or negative outstanding
   - **Prioritise by**: supplier importance signal, days overdue, early-payment discount window
4. Group included bills by supplier; per supplier, calculate total, list bill references, and earliest due date.
5. Present in chat:
   - Pay schedule table (supplier / bill count / total / earliest due)
   - Excluded bills list with the exclusion reason per bill
   - Grand total, supplier count, vs available bank balance check
6. For each supplier on the schedule, draft a remittance advice:
   - Use `Utility_GeneratePDF` (or `Utility_GenerateWord` if PDF unavailable; `tools_search` if names differ) per supplier
   - Include: supplier name, payment date, bill references, line totals, grand total, payment method
   - Save with naming `<client>-remittance-<supplier>-<yyyy-mm-dd>.pdf`
7. Optionally, draft the remittance email per supplier (don't send; user reviews and sends via `Workflow_SendReminder` or manually).
8. Summarise the next steps explicitly: "Review the schedule, post the pay run in the ledger, generate the ABA file from the ledger (v1 does not produce the ABA file), then send the approved remittances."

Use the `payment-run` skill for inclusion/exclusion rules, supplier-prioritisation heuristics, and remittance template structure. Never auto-pay. **v1 limitation**: ABA payment file is generated by the ledger, not by this plugin — surface this in every run summary.
